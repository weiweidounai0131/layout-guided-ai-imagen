# 画板交互与视觉设计规范

版本：0.2.11（公开 Skill 命名迁移、候选版式目录、交互响应式与历史图标规范）  
适用范围：Layout-Guided AI Imagen V1.1 本地画板、MCP Apps 宿主面板与普通浏览器降级页

## 1. 目标与边界

画板是“结构约束与确认”界面，不是成品海报编辑器，也不是生图预览器。用户在这里选择候选、表达局部要求、确认一个可追溯的布局版本；生图必须在确认签名、同一 revision 的双 PNG 与 detail constraints 校验、逐文件原子写入和 generation preflight 全部通过后，继续回到对话执行。

本规范只处理画板的入口、状态反馈、确认后的可恢复编辑、响应式布局与可访问性。它不引入第二种出图模式，不把画板中的字体、字号、色块、边框或朴素文字视为成图必须复刻的视觉样式，也不降低真实 UI 确认门槛。

## 2. 本次问题与根因

1. 顶部关闭入口原本调用普通网页的 `window.close()`；但当前画板由 Codex 宿主面板/宿主管理的 tab 承载，并非脚本通过 `window.open()` 创建。脚本通过 `window.open()` 创建的窗口在特定情况下可能可关闭，决定因素不是同源关系；宿主或浏览器 UI 打开的普通页面没有可靠的页面关闭权限，随后仍显示“可从当前任务关闭画板”，形成了宿主能力不存在时的虚假反馈。
2. 确认成功后的反馈弹层只负责反馈层自身的关闭，不能等价于关闭 Codex 宿主面板。原文案把“关闭提示”与“关闭画板”混在一起，导致用户预期与实际能力不一致。
3. 已确认会话再次打开时，确认按钮虽然被禁用，但没有在按钮附近说明“已确认哪个版本、为什么只读、如何安全返回编辑”。用户因此难以理解为什么不能再次确认。
4. 公共工作流先用 `open_in_codex` 打开 URL，再用浏览器自动化检查并再次创建同一 URL 的 tab，产生双重画板。入口必须是单一、幂等的宿主打开动作；只有该动作明确失败才允许降级打开。
5. 工作区使用固定列最小宽度、工具条和底部操作区缺少窄容器策略。在 1024/768 CSS px、宿主右栏约 560/390 CSS px 或 200% 浏览器缩放下，容易出现水平溢出、操作遮挡和画布可视坐标与 CSS 缩放不一致。

## 3. Apple HIG 依据与产品化取舍

以下是 Apple 官方人机界面指南的依据。官方单页在当前环境以 JavaScript 壳加载；条款核对以 Apple 官方 HIG 的可访问正文/索引内容为准，网页链接用于追溯，不把原生 Liquid Glass 的实现细节强制移植为 Web 玻璃效果。

- [Design principles（网页）](https://developer.apple.com/design/human-interface-guidelines/design-principles) / [官方正文数据](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/design-principles.json)：清晰反馈、用户掌控、可恢复、层级与上下文；对应本产品的状态带、返回编辑和明确的失败提示。
- [Modality（网页）](https://developer.apple.com/design/human-interface-guidelines/modality) / [官方正文数据](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/modality.json)：模态应有明确收益，标题说明任务，并提供清晰的退出方式；对应确认反馈弹层只承担短暂反馈，关闭不等于关闭宿主画板。
- [Toolbars（网页）](https://developer.apple.com/design/human-interface-guidelines/toolbars) / [官方正文数据](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/toolbars.json)：工具应有意图、分组和一致位置；对应紧凑工具条、可见焦点与窄宽度下可换行/滚动。
- [Feedback（网页）](https://developer.apple.com/design/human-interface-guidelines/feedback) / [官方正文数据](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/feedback.json)：反馈应靠近相关对象、可被辅助技术读到，警告只在需要打断时出现；对应 `aria-live` 状态、成功/断线/保存色调和不伪报成功。
- [Layout（网页）](https://developer.apple.com/design/human-interface-guidelines/layout) / [官方正文数据](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/layout.json)：根据实际可用空间适配、保持安全区、在不同尺寸预览；对应 CSS 容器、断点、`min-width: 0` 与宿主窄栏策略。
- [Typography（网页）](https://developer.apple.com/design/human-interface-guidelines/typography) / [官方正文数据](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/typography.json)：优先可读性、层级和随文字尺寸变化的适应性；对应系统字体、短标签与不依赖极小字号承载关键语义。
- [Accessibility（网页）](https://developer.apple.com/design/human-interface-guidelines/accessibility) / [官方正文数据](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/accessibility.json)：让人能够感知、理解和操作界面；对应键盘焦点、按钮名称、禁用原因、颜色不作为唯一状态和 reduced-motion。

Apple 的原则是指导；下列尺寸、断点、颜色和文案是本产品为 Web/MCP Apps 画板作出的具体决策，不声称是 Apple 的强制数值。

## 4. 交互状态与真实语义

### 4.1 单一打开入口

公开 workflow 在拿到 `browser_url` 后，首先调用宿主的 `open_in_codex`。该调用返回成功即视为画板已打开，不再用浏览器自动化检查后重新创建 tab。只有宿主明确返回失败、超时或不可用时，才允许调用已记录的浏览器降级入口，并在状态中标记“已使用浏览器降级”。同一个 session 的重复打开必须复用同一 URL，不创建第二个监听器或第二个页面。

### 4.2 反馈层与宿主画板关闭能力分离

确认成功后，弹层必须显示“已收到你的确认，请回到对话查看后续生成”，并提供真实的 10 秒倒计时、立即关闭和自动关闭。倒计时只承诺关闭反馈弹层。

| 环境能力 | 用户可见行为 |
| --- | --- |
| 宿主提供并成功执行受支持的 dismiss/close transport | 只在调用成功返回后，把画板标记为“已关闭”，同步状态；不依赖 `window.close()` 猜测结果。 |
| 宿主存在但没有 dismiss contract，或调用失败 | 关闭反馈弹层，保留画板，明确提示“提示已关闭，画板仍保留；请回到对话”。不声称已关闭窗口。 |
| 普通浏览器标签页 | 不调用或不宣称成功调用 `window.close()`；10 秒后关闭反馈弹层，画板继续可查看，用户自行返回对话。 |

“关闭提示”永远不关闭确认数据。背景点击仅关闭反馈弹层；宿主关闭失败不能回写为成功，也不能绕过确认和 release。

当前 0.2.9 目标宿主没有可调用的 close-panel/dismiss contract，因此实现不调用
`window.close()`，也不猜测或编造 `dismiss` 接口。画板顶部显示“如何返回对话”
指导按钮，只把用户引回原对话，不执行关闭；确认后的反馈弹层按钮、背景点击和
`Escape` 仍只关闭提示层，画板与确认材料继续保留。未来若宿主公开受支持的关闭
transport，必须先做能力探测，并只在 transport 明确返回成功后显示“画板已关闭”。

### 4.3 已确认版本与返回编辑

确认成功后：

- 会话信息显示“已确认 · v{revision}”，同时保留候选名和确认时间/状态的可读摘要。
- “确认当前方案”按钮 disabled，并在其旁显示：“此版本已确认，当前只读。需要调整时点击‘返回编辑’；产生新版本后需重新选择并确认。”禁用不能只靠降低透明度表达。
- “返回编辑”是显式、可恢复的动作：服务端为同一候选创建一个新的 revision，清除当前待确认选择/确认签名，状态回到 editing；原确认版本保留在历史中，不覆盖、不自动生图。
- 新 revision 产生后，用户必须重新点击候选、提交修改（如有需要）并点击确认。回到编辑不会自动选择、自动确认或触发生图。

返回编辑的服务端动作以同一候选当前 confirmed revision 为输入，先把旧
confirmation 元数据写入本地 `confirmation_history`，再把当前 SketchDocument 的
revision 加一并恢复为 `editing`；current confirmation、候选选择和仍未消费的
confirmation intent 会清空。旧版本的 JSON、双 PNG、detail constraints 与
`confirmation.json` 保留在原候选/version 目录中。任何写入或校验失败都不会写入
current confirmation 指针；孤立的中间文件不代表确认成功，页面不得把它报告为已确认。

### 4.4 细节约束与确认边界

detail constraints 不是只计数的附属文本。确认时必须逐条匹配同一
SketchDocument 的 `annotation_id`、`detail_id`、`target`、`anchor`、`instruction`、
`category`、`polarity`、`status` 和 `must_not_render`；目标缺失、锚点漂移、说明错配或
可渲染标记均拒绝确认。确认材料写入采用逐文件 temp-then-rename，最后才保存
session 的 confirmation 指针；因此任何中途失败都保持 generation preflight
`allow: false`，不能宣称完成跨文件事务。

### 4.5 历史与稳定自适合窗口

撤销/重做属于画板编辑历史，不属于宿主状态，因此与选择、画笔、形状等工具
放在中央浮动工具条的独立 `history` 组中。组前后使用可见分隔符；两个按钮都
使用标准弯箭头和明确的中文 `aria-label`/tooltip，并在没有可用历史时真正
`disabled`，同时保留可见的禁用对比度。顶部右侧只呈现实际连接、保存、导出等
状态，不保留孤立的装饰性历史图标；“如何返回对话”仍是顶部真实的指导入口，
不是关闭按钮。0.2.10 将两个图标改为内联 18×18 SVG 弧形箭头，统一
`stroke-width: 1.65`、`stroke-linecap: round`、`stroke-linejoin: round`；不依赖
字体字符，按钮尺寸、命中区、焦点、hover、disabled、快捷键和 history 组布局不变。

产品主动不提供用户控制的局部视图缩放：不显示 `−`、百分比、`+` 或“适合窗口”
按钮，也不注册 Cmd/Ctrl 缩放快捷键，避免把画布局部视图误解为对象缩放。画布只
在容器测量或窗口 resize 时自动等比 fit；自动 fit 只改变 Fabric 的 CSS 展示尺寸，
不得改写 `SketchDocument.canvas`、对象坐标、提交 revision、PNG 导出尺寸或确认材料。
命中测试与拖拽仍映射到原逻辑坐标，导出始终使用 PosterBrief 逻辑尺寸。

### 4.6 候选版式目录与示意缩略图

0.2.9 起，候选不再由固定的 A/B/C 模板组成。产品维护
`layout-archetypes/1` 目录；当前包含中心英雄、大字主导、图文分割、上下分区、标题
突出、网格模块、框景构图、对角动线、全幅沉浸、留白极简、信息密集分层和编辑网格
12 个 product-owned archetype。每项有稳定 `id`、中文名、适用/避用信号、composition
grammar、slots、difference axes、归一化 hero geometry 与抽象 schematic。

OpenAI 官方公开材料只作为设计启发边界：其 Images 2.5 文章确认 Sketch 可作为最终
图像的视觉参考，并以 flyers、product photos 等格式模板帮助开始创作；官方没有公开
完整的版式目录。本产品目录因此不声称是官方完整列表，也不把截图标签当作产品事实。

本地 selector 从 PosterBrief 的文案长度/密度、主视觉、用途和风格信号确定性评分，
再按 difference axes 去重后选出 3 个实质不同候选；不调用图像模型或额外大模型。其
selection policy 明确标记为 `deterministic_scoring` + `local_fallback`，并将真实模型审美
选择标为 `unverified`。候选 session 记录 archetype id/name、score、selection rationale
和 schematic，旧 session 缺少这些可选字段时仍按原 schema 读取，并由界面使用通用版式
示意回退。

左侧缩略图只画 schematic 的结构块、线和抽象主视觉形状，不绘制完整画布的真实文字或
素材预览；缩略图的 `data-archetype-id` 必须与右侧当前候选元数据一致。这样用户比较的是
版式关系，右侧画板才承担实际布局内容的查看与确认。

## 5. 视觉与布局规范

### 5.1 基础视觉

- 使用系统无衬线字体栈，标题、状态、说明采用三层层级；关键动作不依赖小于 10px 的文字传达。
- 保持浅色、低阴影、细分隔线和浅蓝主动作，以区分画板编辑状态与确认动作；不把 Liquid Glass 作为 Web 必须效果。
- 触控/鼠标按钮的可操作区域目标不小于 40px；焦点使用可见的 2px 描边和 3px 外扩，不以颜色唯一表达选中、错误或在线。
- 中央浮动工具条维持“编辑工具 / 历史”两个语义组，组间使用分隔符；窄宽度下允许换行或横向滚动。颜色盘永不遮挡画布和底部确认。
- 顶部右侧只放真实状态；撤销/重做不再单独悬挂在右上角。所有按钮可操作区域不小于 40px，关键语义使用不小于 12px 的可读文字或同等清晰的图标名称。

### 5.2 可用空间与断点

断点按 CSS 可用宽度而非设备型号决定：

| 可用宽度 | 布局决策 |
| --- | --- |
| ≥ 1180px | 候选 / 画布 / 说明三列；中列使用 `minmax(0, 1fr)`，两侧不挤压画布。 |
| 920–1179px | 仍可三列，但减少侧栏与间距；所有 grid 子项必须允许收缩。 |
| < 920px | 候选、画布、说明纵向堆叠；候选与说明可用卡片网格。 |
| < 560px | 工具条、状态、输入和 footer 分组纵向排列；操作区不横向溢出。 |

宿主右栏 560px/390px 与浏览器 200% 缩放按相同的 CSS 窄宽度规则处理；不通过 JavaScript 读取设备像素比来缩放业务坐标。画布实际坐标仍由 Fabric 的对象坐标保存，显示层只做自动等比 fit；窗口 resize 后重新计算展示尺寸，不改写已提交的对象坐标。实现使用 Fabric `cssOnly` 尺寸更新：backstore 保持 PosterBrief 的逻辑宽高，CSS 展示宽高由画布容器实时测量，命中测试和 PNG 导出继续使用业务坐标。

以下是本产品的 Web/MCP Apps 验证目标，不是 Apple 的强制数值：

| CSS 可用宽度 | 验证重点 |
| --- | --- |
| 1440 | 三列完整工作区，工具、候选、说明和 footer 同时可见。 |
| 1024 | 三列收缩，中央画布使用 `minmax(0, 1fr)`，无固定最小列溢出。 |
| 768 | 候选/画布/说明纵向堆叠，确认操作仍在视口内。 |
| 560 | toolbar、状态和 footer 开始纵向分组，颜色盘换行不遮挡。 |
| 390 | 输入、状态/回退、确认说明、操作按钮单列排列，反馈卡片可滚动。 |
| 200% | 以浏览器提供的 CSS 视口重新走上述断点；不改变 SketchDocument 坐标。 |

### 5.3 区域安全

- `workspace`、`canvas-panel`、`footer` 的 grid/flex 子项设置 `min-width: 0`；页面默认不产生水平滚动。
- 画布容器只在自身需要时滚动，工具条、画布和颜色盘之间留出可见间距；窗口 resize 后自动 fit 不遮挡可交互画布区域。
- footer 拆为“状态/回退”“自然语言修改”“确认与读取操作”三个完整分区；窄宽度下按“状态/回退 → 自然语言修改 → 确认说明 → 操作按钮”单列排列。已确认只读时不同时展示可编辑修改表单；点击“返回编辑”并生成新 revision 后才恢复。
- 反馈弹层使用安全内边距、最大高度和内部滚动；在窄屏和大文字下仍能看到标题、倒计时与关闭按钮。

## 6. 状态、键盘与动效

状态至少区分：等待需求、AI 已连接、保存中、已保存、等待用户确认、已确认只读、返回编辑、断线和失败。状态文字须与实际服务端事件一致；未领取 pending、只读或失败不能显示成功。

键盘可到达候选、工具、输入、返回编辑、确认和弹层关闭；弹层打开时焦点进入弹层，关闭后恢复原焦点。`Escape` 关闭反馈弹层，不取消确认。所有图标按钮都有中文 `aria-label`，动态状态使用适度 `aria-live`。

在 `prefers-reduced-motion: reduce` 下去除位移、弹性和倒计时动画，仅保留状态文字与必要的颜色变化；10 秒计时仍是真实计时，不以动画进度作为业务计时来源。

## 7. 验收矩阵

1. 单入口：`open_in_codex` 成功后只存在一个画板 tab；显式失败时才验证浏览器 fallback。
2. 反馈：确认成功显示正确文案，10 秒后仅弹层自动关闭；立即关闭、背景/ESC 关闭、重复事件去重、失败不显示成功。
3. 关闭：宿主有 dismiss 能力时只在返回成功后显示已关闭；普通网页显示“画板仍保留”，不伪报 `window.close()`。
4. 只读：重新打开已确认 session 显示候选/版本/只读原因；Confirm disabled；返回编辑创建新 revision，旧确认仍可追溯且不会生图。
5. 编辑工具：撤销/重做位于中央浮动工具条 history 组，具有分隔符、tooltip/aria、真实 disabled；顶部右侧无孤立历史图标。
6. 自动 fit：无用户 zoom 控件、状态或快捷键；resize 后展示尺寸自动适配，SketchDocument 坐标、导出尺寸、revision/hash 不变；命中/拖拽仍映射原逻辑坐标。
7. footer：编辑态为“状态/回退 + 自然语言表单 + 操作区”分区；确认态隐藏可编辑表单、显示只读摘要与返回编辑；唯一主动作明确，所有按钮 bounds ≥40px。
8. 布局：1440、1024、768、560、390、195 CSS px，100%/200% 缩放下检查无横向溢出、底部确认可见、工具/状态/输入不遮挡；键盘焦点和 reduced-motion 均通过。
