# V1.1 contract freeze — Stage 0 baseline

Status: `PARTIAL` until the local canvas, persistence, dual export, operation recovery, and host capability evidence are all verified in the target environments.

## Scope

V1.1 uses a product-owned `SketchDocument` JSON rendered by a small Fabric.js canvas. The product is a layout-guided AI image-generation workflow, not a general-purpose editor. The confirmed layout is a visual framework; user-provided people, products, logos, scenes, or style images remain separate reference images.

## Frozen boundaries

- Supported layout object types: text, rectangle, rounded rectangle, ellipse, image placeholder, and freehand path.
- Supported annotations: numbered detail markers and detail notes with stable D-numbers, anchor points, targets, and `render_in_final=false`. Legacy `detail_arrow` records remain readable but are rendered as markers.
- Detailed layout baseline: required copy is represented by positioned text objects with `copy_ref`; major visuals are represented by `image_placeholder` objects with `asset_ref` and `asset_description`.
- AI and user changes use ordered, atomic, idempotent operation batches.
- Layout state is local by default. Logs record status, request identifiers, cursors, revisions, and error categories, not full copy or image data.
- The local session contract is now `layout-session/4` (migrated from `/2` or `/3` on first access); candidate state remains under `candidates/<candidate_id>/` with initial, current, and revision files. Stage 4 adds a renewable listener lease and a private `layout-requests/<request_id>.json` record so a pending natural-language request can be recovered without putting its text in `session.json` or the operation journal. The 0.2.3 safety migration also records sanitized UI selection and one-time confirmation intent state; raw cookie/intent tokens are never exposed in snapshots.
- A current `user_ui` confirmation makes the confirmed candidate revision read-only. A signed workbench `return-to-edit` action creates the next revision, clears the current confirmation/selection/issued intent, and preserves the prior confirmation record and files in `confirmation_history`; it never starts image generation. Every detail constraint must match its annotation identity, target, anchor, instruction, and non-renderable status.
- Confirmation requires an explicit browser/MCP Apps UI selection and click-derived one-time intent, plus the same candidate revision to produce `current.sketch.json`, `layout.clean.png`, `layout.annotated.png`, and `detail-constraints.json` before a generation package exists. A persisted `confirmed_by: "user_ui"` record and `generation_preflight` allow result are required before any generation preview or dispatch.
- Image generation requires a host tool that explicitly supports both image generation and image input. The first request contains the confirmed visual framework plus the complete creative prompt; user reference images are added separately when the host permits them.

## 0.2.4 contract amendment (historical baseline retained)

The framework remains broad structural guidance rather than pixel or visual-style replication. Generation requests now expose `hard_constraints`, `soft_layout_guidance`, and `creative_freedom`; canvas typography and placeholder styling are soft unless the user explicitly locks them. The formal preview reads the persisted confirmation and supplies absolute local refs, while preserving the fail-closed human confirmation gate.

## Current Stage 0 implementation boundary

This baseline replaces the previous Draw.io Embed feasibility prototype. The old XML files and evidence remain historical artifacts only. Stage 0 does not claim candidate generation, production image generation, refinement, cross-computer packaging, or Desktop modal support until those paths have real evidence.

## Dependencies

- Fabric.js is pinned to `7.4.0` and distributed with the plugin under its MIT license.
- The same session API serves the local browser and MCP operations.
- SSE is preferred for committed operation batches; cursor polling is the fallback. WebSocket is not required for MVP.
